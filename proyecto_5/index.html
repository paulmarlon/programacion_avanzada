TEMA 1

1. Gestión de Memoria Dinámica

Administración del Stack vs. Heap: nullptr, delete y delete[]

1.1 La Analogía del Casillero Universitario

🏫 Memoria Estática (Stack): Es como un pupitre asignado el primer día. Ya tiene dueño, tamaño fijo y se libera solo cuando termina la clase.

🏢 Memoria Dinámica (Heap): Es como alquilar un casillero (locker) en recepción. Lo solicitas en tiempo de ejecución (new), usas el espacio exacto que necesitas y tienes la obligación de devolver la llave (delete). Si no la devuelves, nadie más podrá usar ese casillero (Fuga de memoria / Memory Leak).

1.2 Operadores Clave en C++

  • nullptr: Puntero nulo seguro. Indica explícitamente que el puntero no apunta a ninguna dirección de memoria válida ("casillero desocupado").
  • delete ptr;: Libera un objeto individual solicitado previamente con new.
  • delete[] arr;: Libera un bloque completo de memoria contigua (arreglo) reservado con new T[N].

1.3 Código Fuente: Asignación y Libere

// Reserva dinámica de memoria
int* notaEstudiante = new int; 
*notaEstudiante = 100;

// Liberación correcta
delete notaEstudiante; 
notaEstudiante = nullptr; // Evita punteros colgantes (Dangling Pointers)

// Reserva de arreglo dinámico de estudiantes
int totalEstudiantes = 45;
int* listaNotas = new int[totalEstudiantes];

// Liberación de arreglo dinámico
delete[] listaNotas; 
listaNotas = nullptr;
TEMA 2

2. Paradigmas y Trazabilidad en Eficiencia

Definición de Eficiencia: Velocidad, Precisión y Esfuerzo Adecuado

2.1 Los 3 Pilares de la Eficiencia (Ing. MACRO)

  • ⚡ Velocidad: Tiempo de ejecución reducido al procesar grandes volúmenes de datos (ej. consultar 300+ registros).
  • 🎯 Precisión: Exactitud algorítmica sin margen de error lógico ni inconsistencia de datos.
  • 💪 Esfuerzo Adecuado: Uso óptimo de hardware (CPU y RAM) sin desperdiciar recursos del sistema.

2.2 Analogía: La Fila de la Fotocopiadora

Si 100 estudiantes necesitan sacar fotocopia de la misma práctica:
❌ Ineficiente: Que cada uno haga la fila individualmente para sacar 1 copia.
✔️ Eficiente (Velocidad, Precisión y Esfuerzo): Un delegado saca 100 fotocopias juntas en un solo pedido y las distribuye en el aula. Mismo resultado, 99% menos de esfuerzo y tiempo.
TEMA 3

3. Complejidad de Algoritmos

Notación Asintótica: Big-O ($O$), Omega ($\Omega$) y Theta ($\Theta$)

3.1 La Notación Big-O ($O$)

Mide el peor escenario posible del comportamiento de un algoritmo a medida que el número de datos ($N$) tiende al infinito.
Notación Nombre Ejemplo Universitario
$O(1)$ Constante Buscar a un estudiante sabiendo su número exacto de asiento.
$O(\log N)$ Logarítmico Búsqueda binaria en una lista de asistencia ordenada por apellido.
$O(N)$ Lineal Tomar asistencia nombrando uno por uno a los $N$ alumnos.
$O(N^2)$ Cuadrático Comparar a cada alumno con todos los demás para formar parejas.
TEMA 4

4. Estructuras Lineales: Pilas y Colas

Operaciones Push, Pop, Colas Circulares y Principio FIFO/LIFO

4.1 Pilas (Stack - LIFO)

🥞 Principio LIFO (Last In, First Out): El último en entrar es el primero en salir.
Ejemplo: La pila de exámenes entregados en el escritorio del docente. El último estudiante en dejar su examen lo pone encima de la pila, y será el primero que el docente revise.
  • Push(): Apilar / Insertar elemento en la cima.
  • Pop(): Desapilar / Eliminar elemento de la cima.

4.2 Colas (Queue - FIFO y Circulares)

🚌 Principio FIFO (First In, First Out): El primero en llegar es el primero en ser atendido.
Ejemplo: Fila en caja para pagar la matrícula.
Cola Circular: Estructura donde el último posición se conecta nuevamente con la primera. Evita el desperdicio de memoria al reutilizar los espacios liberados por las operaciones de consumo.
TEMA 5

5. Listas Enlazadas

Estructura de Nodos, Campos de Datos y Punteros de Enlace

5.1 Estructura del Nodo

🚂 Analogía del Tren / Búsqueda del Tesoro: Cada vagón (Nodo) contiene la carga (Dato) y un enganche metálico (Puntero `siguiente`) que se conecta con el siguiente vagón. 
struct Nodo {
    int datoEstudiante;  // Carga útil de información
    Nodo* siguiente;     // Puntero de enlace al siguiente Nodo
};

// Creación de un nodo individual
Nodo* nuevoNodo = new Nodo();
nuevoNodo->datoEstudiante = 95;
nuevoNodo->siguiente = nullptr;
TEMA 6

6. Auditoría de Eventos y Registros Before/After

Trazabilidad de cambios, logs transaccionales e integridad de datos

6.1 Registros Before / After

Técnica de auditoría requerida en sistemas transaccionales para registrar la trazabilidad de cualquier modificación realizada en la base de datos o memoria.
  • Before (Antes): Captura el estado original del registro antes de la operación.
  • After (Después): Captura el estado resultante tras la ejecución del cambio.
